# Recommendation Engine — Institutional Grade
## Definition
A recommendation is NOT advice.
A recommendation is:
→ A **precise capital reallocation decision that improves net financial outcome**
---
# CORE FUNCTION
Transform insights into:
→ Executable, prioritized, and optimized financial decisions
---
# RECOMMENDATION GENERATION LOGIC
## Step 1: Input
Derived from:
- Insight engine output
- LAMU model
- Monte Carlo simulation (if applicable)
---
## Step 2: Feasibility Check
Ensure:
- Liquidity constraints satisfied
- No violation of capital hierarchy
- Risk within acceptable bounds
---
## Step 3: Optimization
Determine:
- Optimal £ amount
- Optimal source of funds
- Optimal destination
- Optimal timing
---
## Step 4: Trade-off Analysis
Where applicable:
- Compare multiple allocation options
- Quantify differences
---
# RECOMMENDATION TYPES
## 1. Reallocation
Move capital from low-utility → high-utility
---
## 2. Reduction
Reduce inefficient positions (e.g. high-interest debt)
---
## 3. Optimization
Improve structure (tax, allocation mix)
---
## 4. Timing-Based
Act before deadlines or compounding loss
---
# RECOMMENDATION STRUCTURE
Each recommendation MUST include:
1. **Action**
→ What to do
2. **Amount**
→ Exact £
3. **Source**
→ Where funds come from
4. **Destination**
→ Where funds go
5. **Outcome**
→ Quantified improvement
6. **Time Context**
→ Immediate / horizon-based
---
# ADVANCED (REQUIRED FOR STRUCTURED USERS)
## Scenario Comparison
Present:
Option A (current)
Option B (recommended)
Include:
- Median outcome
- Downside
- Net difference
---
## Partial Allocation Logic
Avoid binary decisions.
Example:
- Split capital between debt repayment and investing
---
# PRIORITIZATION
Rank recommendations by:
1. Net financial impact (£)
2. Certainty (guaranteed vs probabilistic)
3. Urgency
4. Complexity
---
# RECOMMENDATION QUALITY STANDARD
## Weak (INVALID)
"You should invest more"
## Acceptable
"Consider increasing investments"
## BOCY-Level (REQUIRED)
"Move £20,000 from low-yield cash into ISA this month → increases expected return by £X and eliminates future tax on gains"
---
# EXECUTION PRINCIPLE
A valid recommendation must be:
→ Immediately actionable
→ Clear without interpretation
→ Financially meaningful
---
# USER DECISION SUPPORT
Recommendations must reduce:
- Cognitive load
- Uncertainty
- Decision friction
---
# HARD RULES
- No vague language
- No non-quantified outcomes
- No recommendation without clear superiority
---
# SYSTEM OBJECTIVE
User must feel:
→ "This tells me exactly what to do"
→ "This improves my financial position in a measurable way"
→ "I trust this decision"
